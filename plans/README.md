## Vetted backlog (found, confirmed, not yet planned)

Highest-leverage first. IDs refer to the audit session; evidence was verified against `90411f2`.

**Security / correctness**
- PLUGIN-08 — users collection spreads `...existingUserCollection?.access` LAST (`plugin/lib/build-collections/users/index.ts:~256-267`), letting a pre-existing users collection silently overwrite the plugin's access guards (same class as fixed P1-4, higher-value collection). S effort.
- PLUGIN-05 — `getSafeRedirect` (`plugin/payload/utils/get-safe-redirect.ts`) is prefix-check based; encoded control chars (e.g. `/%09/evil.com`) survive and browsers normalize to protocol-relative URLs. Harden with `new URL(value, base)` origin check + control-char rejection + unit tests. S effort.
- ADAPTER-11 — after-signup invite middleware deletes the token before assigning the role with no error handling/compensation; a failed role update burns the invitation and skips `originalAfter`. S–M effort; preserve delete-first single-use semantics (P0-4).
- PLUGIN-03 — `AdminButtons` calls `useMemo` after an early `return null` (`admin-buttons/index.tsx:22-34`): conditional hook → React 19 crash of the edit view when `id` resolves. S.
- PLUGIN-11 — admin-invite modal caches the generated link; switching role then Copy/Send distributes a token for the previously selected role. S.
- ADAPTER-10 — `normalizeData` lowercases all role values on write; any camelCase configured role breaks select validation/admin checks. S, MED risk (existing data).
- PLUGIN-18 — self-update access returns `false` when Payload evaluates permissions without `id`/`data`, making the admin UI render the account view read-only for non-admins; also strict `===` id comparison across idType. S, MED risk.
- ADAPTER-08 — `updateMany`/`deleteMany` discard Payload's per-doc `errors` array; partial failure (e.g. "revoke all sessions") reports success. S.
- PLUGIN-17 — `refresh-token.ts` looks up the `dontRememberToken` signed cookie without its `__Secure-` prefix, so "don't remember me" is ignored on HTTPS deployments. S.
- PLUGIN-04 — optional username field rejects empty string (regex refine ignores `required: false`), blocking default-config admin signup when the field is left blank. S.
- ADAPTER-12 — `findMany` single-ID fast path ignores `offset`/`sortBy`; `findOne`/`update` return `undefined` instead of `null`. S.
- PLUGIN-09/10/13/14/15/16/19 — smaller admin-UI issues: silent passkey fetch/delete failures; dead loading state on social/passkey buttons; soft navigation after passkey/2FA success vs hard reload on password path; hydration-unsafe `error` query read; unsafe `data.token` deref + unmemoized auth client in signup; password policy not enforced client-side on reset/signup; token field keyed on hardcoded name. S each.
